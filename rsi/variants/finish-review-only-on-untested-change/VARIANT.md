# Run the finish review only when the change is empty, untested since the last edit, or leaves new untracked files

hypothesis: Now every run that stops gets one more round: the harness shows the task and the diff and asks for a requirement-by-requirement re-check. When the agent has already run a test command after its last edit, that round almost never changes the diff. It re-runs what was just run, or turns into a long guess at what upstream did or what unseen checks expect, all at the run's largest context. With this change the review fires only on an objective gap: no change at all, no test command since the last edit, or untracked files the agent created (files already untracked before its first tool call don't count). A tested, non-empty change ends the run when the agent stops. The diff handed in is the one it had before the review, so passes should hold, with fewer requests, tokens and minutes per run. The runaway guard, thinking cap, system prompt and the review text itself are unchanged.

evidence: In the parent's 26 runs only 3 edited anything after the first stop. django-10973 (passed) added a `runshell_db` alias after about 3.4K tokens of guessing hidden-test names; this variant keeps the review there because the edit was untested. django-15987 (failed) restored an error message and narrowed the fix to one expression, and still failed. sphinx-7985 (failed) only moved a CHANGES bullet. fresh-eyes-finish-review reports zero review edits in the grandparent's runs. The review phase is where hidden-test/upstream talk peaked: 63, 22, 13 and 6 such sentences in django-10973, sphinx-9281, django-15987 and sphinx-7985 (3 of these 4 failed), and about 0 in most passed runs. In sphinx-9281 (failed) the review turn is where the agent wrote "The hidden tests probably verify the upstream fix", tried `pip download`, and kept `ValueA` anyway. I replayed each run's tool calls through the extension's own test and edit patterns. 23 of 26 runs had a non-empty change tested after the last edit at the first stop, so the review would be skipped. The other 3 (django-10973, django-14608, sympy-14248) keep it. In those 23 runs the review cost 45 of 773 requests (5.8%) and 20.2K of 405K output tokens (5.0%), all at peak context. No run left throwaway files in the repo. try-variant on toy repos: a fix tested with pytest ended at the agent's first stop with the skip entry. An unchecked fix got "finish review (untested change)" and one more round. A mocked-API check of the settle hook covers no git, git failing, a capped stop, a context over the limit, pre-existing untracked files, a leftover repro script, `git stash pop` after a test, and an empty diff; every run ends after at most one review.

predicts: "skipped finish review: change tested after last edit" on about 80-90% of runs, and "finish review (...)" on about 10-20%. Requests per task fall by about 1.7 (about 6%) and output tokens by about 5%. Input tokens fall by more, about 10%, since the skipped turns re-send the largest context of the run, and minutes fall a little. Passes stay within noise of the parent, because the skipped rounds almost never changed the diff. It's wrong if passes drop by 2 or more per run, or if the skip share is high but requests and tokens per task don't fall.
