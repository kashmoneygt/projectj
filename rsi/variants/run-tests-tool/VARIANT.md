# Add a run_tests tool: compact pass/fail report, runner discovery, and a before/after comparison that never touches the working tree

hypothesis: Now the agent runs tests through bash and spends turns on the plumbing rather than the fix. It pipes the run through `tail -N` and loses the summary (Django prints "Destroying test database…" after it), then reruns with `grep -E "^(OK|FAILED|Ran)"`, then again with `grep -A30 "^ERROR:"` to see what failed. It passes labels that don't exist and has to dig the import error out. It finds pytest missing and hunts for the repo's own runner. And it checks whether a failure is pre-existing with `git stash` / rerun / `git stash pop`, which risks a tree left without its changes. A `run_tests` tool takes the plain test command, keeps the whole output in a log, and returns the summary line, each failing test with its error line, the labels that could not be loaded, and the last lines. When the command can't start a runner, it lists the runners the repo has. With `compare_with_original` it runs the same command on a copy of the repo at HEAD (ignored build files kept, imports pointed at the copy) and reports which failures are new with the change, which were already failing and which the change fixed. Fewer turns go to test plumbing, regressions the change causes are named instead of being written off as "pre-existing", and the working tree is never stashed.

evidence: About 28% of the bash calls in the parent's transcripts run tests (282 of 1013). A `git stash` baseline check appears in 26 of 75 runs (44 calls), and "pre-existing" in 33 runs. "No module named pytest" appears in 18 runs (11 Django, 7 sympy); in sympy-12096 and sympy-11618 it is followed by about 5 commands hunting for the runner. The run / `tail` hides the summary / rerun with grep / rerun for the traceback chain appears in both sides of the diverged django-16454 (ending in a stash check of a umask failure), django-13012 and django-13128 (bad labels `querysets`, `lookups`, `conditional`), and in the passed django-12774 run. sympy-13551 spends two turns on doctest failures: grep to find which, then a stash to confirm they were pre-existing. In try-variant runs on small repos the model used `run_tests` unprompted, followed the runner hint after `python` was missing, and used `compare_with_original` to set aside two pre-existing failures in one call.

predicts: Most runs that test call `run_tests` ("acted" on roughly 60–80% of runs, with "run_tests with comparison" on 15–30%). Bash calls that run test commands drop by more than half, and plumbing reruns (the same suite rerun only to see its summary or traceback, `git stash` baseline checks) mostly disappear. Runs that test should need about 2–5 fewer requests each, with similar or slightly fewer output tokens and as many passes or slightly more. It's wrong if the agent ignores the tool ("acted" on under 20% of runs), if requests and tokens don't fall in the runs that use it, or if passes drop.
