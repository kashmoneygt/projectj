# Replace pi's generic system prompt with one that settles expected output, failing tests, sibling code paths and recollections by the issue text and the repo

hypothesis: The agent now makes its riskiest calls by guessing what unseen checks will want: it calls new failures in existing tests "old tests that will be replaced", widens a fix to sibling code the issue never mentions, and swaps the issue's literal expected output for a format it remembers from upstream. The parent's in-context finish review then confirms the decision. This variant replaces pi's default system prompt, whose pi-docs block is useless for repo work, with the same tool rules plus a short `deciding_by_evidence` section. Each rule says when it applies. Match the issue's literal expected output exactly when it shows one. For each new test failure, quote the issue sentence that calls wrong what the assertion checks (through the issue's code or a caller, not a sibling), or rework the change until the test passes. Leave a sibling implementation alone if changing it breaks its own tests. Run the callers' tests when a shared helper changes. Treat a remembered upstream fix as a guess. The rules are in view from the first request, so they shape the decision when it's made, not after the agent has committed to it. The thinking cap, nudges and finish review are the parent's, unchanged. `evidence-marker.ts` only records when a test run after an edit shows failures, the moment the rules are for.
