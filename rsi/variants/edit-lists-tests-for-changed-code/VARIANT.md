# edit/write results list the existing tests that reference the function or class just changed

hypothesis: Right now `edit` returns only "Successfully replaced N block(s)". The agent then decides on its own whether to test and where, and it often guesses: it runs a nearby module, invents a test path or label, or runs nothing. With this change, after a successful `edit`/`write` of a tracked, non-test Python file, the tool reads `git diff HEAD` for that file and finds the innermost function(s) and class around each changed spot. It then appends the existing test files, and the test functions in them, that reference those names, found with `git grep -w` over `tests/` dirs and `test_*.py`-style files. At most 2 names and 4 files are listed per edit, each name once per run. Dunder and generic names are skipped, as are names referenced from more than 15 test files. When nothing is found, nothing is added. So the agent learns, at no cost in turns, where the behavior it just changed is pinned down, and runs those tests before finishing. A fix that breaks current behavior the issue never asked to change then fails an existing test while the agent can still react. That is a common way real fixes go wrong in any repo.

evidence: In 73 of 75 parent runs the agent edited a non-test .py file, so the change can kick in on nearly every run. The two runs where it can't are runaway runs with no diff. 10 runs ran no tests after their last edit; 5 of them failed (django-10973, django-12774, django-14404, matplotlib-22871, sympy-14248). In the diverged django-12774 pair, the failing run deleted the uniqueness check in `in_bulk` and never ran tests/lookup, whose `test_in_bulk_non_unique_field` pins that check. The passing run did run tests/lookup. django-10973 searched tests/backends and never found tests/dbshell. On cost, 16 bash errors came from guessed paths that don't exist, and several runs spent turns working out test labels (django-13012, django-13128, django-12774). In a replay of the in_bulk moment on a small repo, the edit result listed `test_bulk_lookup_non_unique_field` and its siblings. The agent ran that test file and, in its final message, named the listed constraint test. When one listed test already failed before the change, the agent checked it with `git stash`, set it aside, and finished without chasing it.

predicts: The "acted" entry appears on most runs (more than 70%). The share of runs that run a listed test file after their last edit goes up, and runs that never test after editing go down. There are fewer errors from guessing test paths or labels. Passes should be equal or higher, mostly on tasks where a plausible fix breaks a neighbouring existing test. Tokens should stay about flat: tool output grows by about 100-300 tokens per run, and a few search turns go away. The idea is wrong if the listed files are run no more often than in the parent, or if runs get longer (chasing failures in listed tests the agent didn't cause) with no gain in passes.
