# Explain test labels that name no module, right in the bash result

hypothesis: The agent often guesses dotted test labels for label-taking runners (a `runtests.py` over a directory of test packages, `python -m unittest`) that don't exist: `contenttypes` for `contenttypes_tests`, `lookups` for `lookup`, `auth`, `save`, `queries.BulkUpdateTests`, `db_functions.datetimes`. The runner reports each one as an ordinary-looking error (`ERROR: x (unittest.loader._FailedTest)`, counted in `FAILED (errors=1)`). The agent's own `| tail` / `| grep "^(Ran|OK|FAILED)"` filter usually hides which test errored. So it reruns the suite to dig out the traceback, does `git stash` baseline checks, runs `python -c "import contenttypes"`, and sometimes concludes its fix broke something. Or it believes tests ran that never did. With this change, a `tool_result` hook (bash only) parses the command: `cd` tracking, quotes, redirections and runner options. It checks every label against the files under the runner's test root. Only when a label names no package, module or class does it append a short note saying which labels don't exist, that the error is from the label and not the code, that those tests did not run, and which labels are close (with the test modules inside the closest package, or where a named class actually lives). It never blocks or rewrites a call, and stays silent when every label resolves. One look at the note replaces the rerun-and-diagnose loop, so the agent runs the tests it meant to run.

evidence: In the parent's runs, `_FailedTest` / "Failed to import test module" shows up in 25 of the 45 runs on a `runtests.py`-style repo (19 passed, 6 failed), 66 times in all, almost always from a made-up label. Those are only the ones a filter didn't hide. The worst cases are long failed runs. django-15957 spent about 13 requests (turns 84–97, context over 60%) chasing `contenttypes`, even checking whether the test suite had deleted directories. django-14792 spent about 9 requests (turns 55–65) on `timezone`, `forms_tests.model_fields`, `template_tests.test_tz` and `template_tests.tz`, including a `git stash` baseline. django-11477 (t61–70) chased `admin`, `urlpatterns_init`, `syndication` and `urls_reverse` with stash checks. Passed runs pay too: django-12273 (t27–39 on `save`, plus `python -c "import save"`), django-13012 (17 hits: `values`, `querysets`, `subqueries`), django-13128, django-17084 and django-13028. Replayed live with try-variant on a small repo with a label-style runner. The note fired on both wrong labels (`text_utils`, `slugify`) with the right package and its test modules. When the agent then guessed a class name that doesn't exist, the next note listed the module's real classes, and the agent's next run used a valid label. The note stayed silent on valid labels. In a third replay, after the repair, the note fired on the issue's own wrong label. The agent read it ("the actual module is `text_utils_tests.tests`") and spent no requests chasing the error. In offline checks on commands taken from the transcripts it flags the bad labels above with the right suggestion (contenttypes_tests, lookup, auth_tests, save_delete_hooks, db_functions.datetime, queries.test_bulk_update.BulkUpdateTests). It stays quiet for valid labels, `$var` labels, heredocs, plain greps that mention runtests.py, non-label runners, file-path labels (`test_x.py`), classes re-exported through `import *`, and unittest packages installed outside the repo.

predicts: "acted" ("explained missing test labels") should show on roughly 30–40% of runs (about half of the runs on runtests.py-style repos, rarely elsewhere). On those runs, fewer requests should go to re-running a suite only to see what errored, to `import <label>` probes and to `git stash` baseline checks after a label error. Expect about 1–3 fewer requests on a typical affected run and many more on the long ones, with total tokens down mostly through fewer late, high-context requests. Passes should hold, maybe rise slightly where a misread `errors=1` sent the agent after its own fix, or where the intended tests never ran. It's wrong if acted runs keep the same number of runtests reruns and diagnosis commands as the parent's (the note is ignored), if tokens per acted run don't fall, or if passes drop (for example, if the agent starts dismissing real errors as label problems).
